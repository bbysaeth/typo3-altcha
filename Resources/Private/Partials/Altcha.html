Always use challenge (uncached endpoint) to avoid form caching issues. - Local mode: Uses an uncached local endpoint for challenge generation - Self-hosted with API key: Uses proxy that forwards with headers - Self-hosted direct: Uses direct URL to server The widget has no `verifyurl` attribute, it only accepts the verification endpoint as `verifyUrl` inside the `configuration` JSON. The internal endpoints are built with f:uri.page rather than written out as `/?type=...`. On a site whose languages all use a path prefix there is no page on `/`, so a hardcoded root-relative URL gets redirected to the default language and returns HTML instead of JSON. {f:uri.page(pageType: 1768669000, language: 'current')} {f:uri.page(pageType: 1768669001, language: 'current')} {f:uri.page(pageType: 1768669002, language: 'current')} Custom texts are picked up by EXT:altcha's own JavaScript and registered in the widget's global i18n store, because v3 dropped the `strings` attribute. {f:render(partial: 'AltchaTranslations')} type="{settings.widgetType}" display="{settings.display}" `auto` has to be omitted entirely when disabled.
